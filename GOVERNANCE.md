# Governance

Toda uses a maintainer-led governance model during the alpha period.

The lead maintainer sets product direction, approves releases, appoints
maintainers, and makes final decisions when consensus is not reached.
Contributors influence direction through issues, discussions, design proposals,
reviews, and sustained ownership of project areas.

Routine changes use pull-request review. Changes to trust boundaries, data
models, authorization, tool approval semantics, or Task lifecycle invariants
must include an architecture note and focused regression tests. Security fixes
may be developed privately and released before full disclosure.

Maintainer status is earned through consistent technical judgment, respectful
collaboration, and demonstrated care for user data. It may be removed for
inactivity, security violations, or conduct violations.
